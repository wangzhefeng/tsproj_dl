C01 · 输入分组

原始需求
用户层、机房层、楼宇层各有独立空间分支，图中省略号允许更多分支。
当前实现
AIDC profile 为算力、IT 电力、配电、暖通、空间、环境六组；机房与楼宇通过 space 的类别属性区分，用户／业务池映射到 compute，而非保留原来三个固定分支。
判断
保留按组建模思想，业务分类已变化。不能将当前图标成对原始三个分支的逐字复刻；模型一般性分组由 schema 决定。

C02 · 空间位置编码

原始需求
每组进入空间注意力前显式加 Space Positional Encoding；图未说明编码基于行号、身份、坐标还是拓扑。
当前实现
不加实体序号位置编码，也不使用实体 ID embedding。静态数值／类别与观测 mask 进入组适配器，拓扑通过类型关系注意力进入；只有 schema 声明的坐标特征才可能作为属性消费。
判断
不是漏画：原图独立加法式 Space PE 没有原样实现；R4 有意选择属性与关系归纳编码，以支持可变实体及同步重排不变性。不能说空间信息全部删除，也不能声称已有几何相对位置编码。

C03 · 池化前实体历史

原始需求
图展示逐时刻的空间分支，再沿时间堆叠；没有独立实体循环单元。
当前实现
每个动态组先用属性适配器，再用同组实体共享的单层单向 GRUCell，生成逐实体因果历史表示；纯静态组无 GRU。
判断
当前模型不只是纯空间 Transformer 接时间 Transformer，而是实体 GRU→空间交互→系统时间建模，避免汇总前丢失实体轨迹。

C04 · 组内空间 Transformer

原始需求
各组 Multi-Head Attention→Add & Norm→Feed Forward→Add & Norm，以 Nx 标重复。
当前实现
各组一层 Post-LN TransformerEncoderLayer，GELU、FFN 宽度 4d_s；加入可学习摘要 token 与实体有效性 mask。配置校验将 spatial_layers 固定为 1。
判断
注意力／残差／归一化骨架保留，但不是任意 Nx 堆叠。摘要 token 在该层参与注意力，输出后被剥离，不直接当作最终组向量。

C05 · 实体级跨组关系

原始需求
各组向量在读出后横向拼接；没有显式画出归属边或跨组实体级消息。
当前实现
组内输出先拼实体轴，再经过两层带类型／方向偏置的关系注意力，按源→接收方方向和显式反向通信开边，随后切回各组。
判断
当前不是仅后期拼接：在组读出前已有跨组信息交互。关系层的图 mask 不代表整个网络只沿物理边传播，因为组内注意力已经混合同组实体。

C06 · 固定宽度组读出

原始需求
每个空间分支输出一个向量，但没有指定从多实体到向量的聚合算子。
当前实现
每动态组可学习 query 对关系增强实体及空组 token 做 cross-attention；拼 log1p(有效实体数) 与观测覆盖率，经 Linear→LayerNorm 得到 d_z 维规范状态。
判断

C10 · 总负荷／下一状态双头

时间模块输出分别经过 Linear 生成总负荷、multi Linear 生成 next embedding。

C11 · 回灌闭环与窗口

原始需求
next embedding 箭头返回 time series；没有画总负荷回灌，也未规定无限增长还是滑动窗口。
当前实现
每步同时追加预测 z 和同一个预测 y，窗口保持 L，生成态 observed=false、generated=true、coverage=0；历史实体编码与未来路径各算一次，之后每步重算时间窗口。
判断
不是把未来真实实体输入空间模块，也不是逐步重跑 GRU；预测状态直接进入系统时间链。当前没有 KV cache；完整递推梯度保留。

C13 · 已知未来路径与 lead

原始需求

当前实现

06 / 现行规格与代码差异

本次不擅自修改模型或改写权威设计来消除差异，先记录事实和真实代价。

D01 · 静态链最终投影层数

实质结构不一致，待裁决

规格
实施规格 §1.3 写为：组输出拼接后 Linear→GELU→Linear 到 d_t。
代码
StaticConditionEncoder.project 实际只有 Linear(G*d_z,d_t)；非线性只存在于每组投影中。
判断
少了规格描述的跨组非线性融合层。不能认为两者一般等价，也不能仅为文档对齐擅自增加层。本次架构图按实际单层 Linear 绘制；后续需决定接受现实现并修规格，还是补 MLP 并升级计算版本、重训验证。

docs/gslaformer/v1/implementation.md:52-56 · layers/gslaformer/spatial.py:86-93 · layers/gslaformer/spatial.py:116-126

D02 · 历史日历特征注入方式

结构表述不一致，通常可做等价表述对齐

规格
实施规格 §1.4 与 temporal.py 顶部说明写为：日历四维经独立 Linear 投影后与其他 token 投影相加。
代码
_window_tokens 把四维日历直接拼在末尾，TemporalEncoder.project 对所有 211 维联合做一次 Linear，再加正弦位置编码；没有单独日历投影模块。
判断
线性层按输入列拆块后，在合并 bias 的条件下可写成独立投影相加，表达能力并不因此必然降低。但当前计算图确实只有一次联合投影，图和模块清单不能虚构第二个 Linear；本次只登记，不改规范或模型。
