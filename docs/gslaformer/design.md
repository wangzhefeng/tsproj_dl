## 1. 目标与非目标

面向不同 AIDC 的单设施总电力负荷，利用算力、IT 电力、配电、暖通、空间和环境对象的历史，在固定 schema 下支持不同数量、观测粒度和合法连接。站点共享参数，但每个请求独立计算，不建立跨站点实时注意力。

完整交付是**共享实体因果历史编码 → 分组空间交互 → 类型关系交互 → 分组状态读出 → 系统因果时间模型 → 总负荷／下一状态双头 → 自由递推**。直接多步输出是必需对照，不能代替双头回灌交付。

首轮仅做合成数据的完整训练、验证、测试、无标签 forecast、重载、新实体与未见站点验收。小时至三天按独立 profile 训练与验收，不能从短 horizon 外推长 horizon 成功。

不包含任意新分组／新特征免训练、未来拓扑切换、节点功率预测、物理守恒、生产规模保证或真实站点效果承诺；不加入图卷积、复杂模型融合或无关主线重构。真实业务采用需后续独立验证。

## 2. 已确定的决策

| ID | 决策 | 对设计的约束 |
| --- | --- | --- |
| D1 | 先完成功能，真实数据验收暂不启动 | 合成结果标 synthetic；无业务数据不阻塞首轮功能实现 |
| D2 | 同 schema 新增实体免重训 | ID 只对齐和审计；属性／观测／关系归纳编码，参数不绑定实体数量 |
| D3 | 通用未来条件，有可靠数据时启用 | 起点可见的完整未来路径；允许未配置或缺失，禁止未来实测替代计划 |
| D4 | 不要求超过对照，但如实报告 | 功能成功与方法收益分开判定 |
| D5 | 关系真实参与计算 | 实体汇总前交换信息，不只保存关系表或拼接 ID |

R4 将应用与联合训练范围明确为跨 AIDC，使用六组对象及多类型关系；这不是新增真实零样本精度承诺。既有决定与 R2/R3/R4 演进原文见[历史记录](archive/design_history.md)。

## 3. 为什么先编码实体历史，再做空间汇总

逐帧集合相同不代表实体轨迹相同。若先对每帧池化，再建系统时间模型，可能永久丢失“哪台设备在持续变化”的信息。因此先按 ID 对齐整段历史，用同组共享的单向 GRU 编码，再逐时刻做空间和关系交互。

实体 ID 不进入可学习查表，不使用任意实体行号位置编码。合法不变性是整段历史、属性、mask、关系同步重排；中途交换两个实体的观测代表不同轨迹，不应被强制视为相同输入。历史编码仍是有限宽度的有损压缩，不保证保留所有预测信息；M1 专门检验这一结构选择。

不同分组使用独立适配器，同组实体和所有时刻共享参数。缺失、尚未生效与 padding 具有不同语义；数据定义由输入输出合同负责，状态更新细节由实施规格负责。

实体因果历史表示写为：

\[
r_t^{(g)}=\operatorname{EntityHistory}_g(X_{\le t}^{(g)},M_{\le t}^{(g)},A_{\le t}^{(g)})
\]

其中 X、M、A 分别是观测、有效性标记和属性条件；只有截至 t 的实体历史可参与。

## 4. 空间、关系与读出为何分开

原 v4.0 图只明确分组空间编码及后期融合，没有定义归属矩阵或实体级跨层消息。[原图](architecture/v4.0.png)是起点，不是当前完整计算图；[当前图示](architecture/architecture.md)表达扩展后的链路。

组内注意力刻画同组对象之间的联系，类型关系层刻画归属、供电、计量覆盖、冷却、任务部署与环境关联。各关系有独立业务方向和合法性，不建一棵万能树；反向通信不代表物理反向供电。多层功率可共同提供信息，不能直接相加成总负荷。

关系交互发生在最终分组汇总之前。首版两层关系交互是工程深度选择，不保证遍历全部电力层级；此前的组内全连接注意力已混合信息，也不能把关系层 mask 解释为整个网络只沿物理边传播。

分组读出采用关系增强后的查询池化，输出固定宽度，避免实体展平绑定数量和顺序。均值池化保留为对照，实体展平不作为正式路径。数量、覆盖率及独立静态属性统计补充规模信息，但不构成功率可加性、单调性或守恒保证。

关系可以被已训练模型忽略。受控参数测试证明路径存在，重训消融评价收益；不能要求任意权重对每次重连都改变预测，也不能把临时删边当成重训因果证据。

\[
z_t^{(g)}=\operatorname{Readout}_g(\operatorname{RelationAttention}(\{\operatorname{SpatialEncoder}_j(r_t^{(j)})\}_j,R_t))
\]

R_t 是当时有效且预测起点可见的关系，读出发生在关系增强之后。

## 5. latent、静态条件和总表旁路

动态分组的读出经各自 LayerNorm 后拼接为规范状态 z；预测头和回灌使用同一坐标。时间模型输入投影、时间编码和 Transformer hidden 不是 z，不能因宽度相同就替代。

\[
z_t=z_t^{(1)}\Vert z_t^{(2)}\Vert\cdots\Vert z_t^{(G)}
\]

此简式仅枚举参与状态拼接的动态组，末项 G 对应 batch 契约的 Gd；不是把纯静态组也加入状态预测。

latent 是**由属性、关系、观测质量条件化的因果历史表示**，不是无噪声物理状态、已证明充分的状态或因果世界模型。混合分组可含静态信息，不承诺完全解耦；纯静态组无 latent 预测头。

静态条件从独立属性链生成，不能用包含动态观测的最后 hidden 冒充静态表示。总表历史是显式旁路：内部测点未必覆盖设施目标边界，不能假设空间分支能够重建总负荷。未来总表输入由同一个预测 y 回填，不另建第二个总负荷状态头。

缺失下的 teacher 表示只是带观测质量的辅助目标。分组软质量避免一个缺失组关闭全系统监督；连续有界方差权重避免近常量处数值跳变。质量和权重都是工程启发式，不是概率置信度或最优性证明。

## 6. 完整未来路径与双头递推

时间链采用显式因果 Transformer，不需要完整 encoder-decoder cross-attention 结构。历史 token 包含 z、总负荷和质量／来源标记，位置与日历分开编码。

对原起点 o 的第 k 步，融合当前历史或回灌 hidden、起点静态条件、完整未来路径的第 k 步表示与 lead(k)，同时预测 y[o+k]、z[o+k]。两个头监督同一下一时刻。

\[
h_t=F(z_{\le t},y_{\le t},q_{\le t},\operatorname{time}_{\le t})
\]
\[
a_{o,k}=\operatorname{Fusion}(h^{roll}_{o,k},c_o,p_{o,k},\operatorname{lead}(k))
\]
\[
\hat y_{o+k}=g_y(a_{o,k}),\qquad \hat z_{o+k}^{(g)}=g_z^{(g)}(a_{o,k})
\]

q 在这里概括时间 token 的质量／来源信息，不表示将未来 teacher 的质量权重作为生产输入；精确字段见实施规格。

FuturePathEncoder 只读取原点已知的整段计划／日历及 mask，允许双向编码；已知计划的后续时刻不是未来未知观测。A、direct 和 AR 得到同一完整信息集，不能让 direct 少看计划前缀，也不能让 AR 在递推中刷新后来发布的计划。

每请求真实历史和未来路径各编码一次；之后只回灌系统 z 与同一步 y，不反解实体值或实体 GRU memory。裁窗、位置和来源标记在训练与预测中一致，生成态不伪装为真实完整观测。未来 teacher 只存在于隔离监督路径。

## 7. 为什么采用两阶段训练

同时更新编码器并拟合 latent MSE，会导致监督坐标移动，也可能通过缩小表示尺度降低损失。一步拟合好不等于多步稳定，因此首版选择先学表示、再冻结表示训练自由递推。

- **阶段 A**：以完整 horizon 的直接多步总负荷监督训练实体／空间及预测链，无 latent loss。相比一步监督，减少只保留短期信息的风险。
- **冻结**：选择 best_A，固定表示生成链、静态链、schema、词表和 scaler，使历史与 teacher 共用稳定坐标。
- **阶段 B**：继承预测链，启用 latent 头；主负荷损失加分组辅助损失，课程逐步增加自由递推长度。短课程不提前终止，最终只在完整 horizon 阶段选最终模型。

\[
\mathcal L=\mathcal L_{\text{load-rollout}}+
\lambda\frac{1}{|\mathcal G_{\text{dynamic}}|}
\sum_{g\in\mathcal G_{\text{dynamic}}}\mathcal L_{\text{latent}}^{(g)}
\]

上式表示主任务与分组辅助任务的组成；有缺失组／horizon 时的有效分母、软质量和方差权重以[精确 reduction](implementation.md#implementation-5-2)为准，不按无效项补零平均。

未来实测只用于 teacher 标签，不进入自由递推。teacher 从同起点历史末端实体 memory 副本延续，生产回灌不读这份状态。短期到完整 horizon 的梯度必须贯通，不能静默 detach 改算法。

代价是冻结后表示不能继续联合适应，且历史总负荷旁路可能使空间分支被忽略。冻结只稳定坐标，不保证状态充分、回灌处于编码器流形或训练一定成功。先用机制任务和回灌诊断判断问题，再考虑 EMA 等额外复杂方案；首版不默认加入。

## 8. 能力边界、风险与评价原则

跨站点能力分层（唯一权威，其他文档引用本节）：

| 能力层次 | 本轮设计要求 | 不应推出的结论 |
| --- | --- | --- |
| 数据通用 | 原始点名映射为统一单位／类型／关系合同 | 所有站点电力架构相同 |
| 结构通用 | 同 schema、可变实体数、空组、未知 ID 可运行 | 任意新对象类型都免重训 |
| 参数共享 | 多个模拟站点共同训练一套模型 | 多站点一定比单站模型准确 |
| 未见站点推理 | 冻结权重／词表／scaler，对独立留出站点预测并报告 | 新站无需校准就有生产精度 |
| 真实迁移 | 将来用真实站点独立回测与可选适配 | 模拟数据能够“确保”真实泛化 |

全局非承诺清单（唯一权威；各主题文档只保留与本地规则直接相关的部分，不再重复展开）：

| 对象 | 不承诺 |
| --- | --- |
| 类型关系层 | 不是电气／热力／管网求解器；边合法不代表物理可行；显式反向通信不代表物理反向供电 |
| latent z | 不是物理状态、充分统计量或因果世界模型；不能逆变换为设备功率 |
| 质量字段（q、coverage、degraded_input 等） | 不是概率置信区间，也不是最优性证明 |
| 合成验收 | 通过不代表真实站点泛化；文档／契约测试通过不代表模型完成 |
| 设备路由 | 明确请求的设备（MPS/CUDA）不可用时报错；任何回退不得记作该设备验证通过 |
| 新实体／新站 | 结构可运行不承诺精度；冷启动标记不代表误差有界 |
| 汇总与读出 | 无功率可加性、单调性或守恒保证 |
| 对照 | 不要求 full 优于 direct/naive；direct 更准时承认工程实现成功，但不声称 latent 回灌有收益 |

同 schema 新实体可复用参数、词表和组级 scaler；没有历史时依靠属性、关系与缺失语义得到带冷启动标记的预测，不保证精度。历史关系和属性按有效时间及起点可见版本选择；未来上下文固定，已知 horizon 内变更的请求明确拒绝。

跨站点通用性分为数据语义兼容、结构可运行、参数共享和留出误差，不能从前一层推出后一层。模拟规则尚未用生产数据校准，不能确保真实泛化；稠密 mask 也不等于稀疏计算，可变节点数不等于无限扩容。

必要对照包含朴素预测、仅总表时间模型、移除空间交互、直接多步与完整模型；实体历史、关系消息／全部关系、latent loss 的消融及运行矩阵由验收协议唯一规定。相同起点信息、切分、目标和评价口径是前提，容量、优化路径及算力差异必须报告。

同权重的固定 z、固定 y 与 teacher 回灌仅作诊断；teacher 使用未来信息，不排名、不选模，也不保证是严格数学上界。direct 更准更快时，仍可承认工程实现成功，但不能声称 latent 回灌有收益。

最脆弱的业务前提是内部动态信息在真实起点可得、可对齐且与目标相关。真实数据阶段需另确认计量口径、采样频率、历史／预测范围、数量与点位、关系版本、到达延迟、数据权限、设备预算和业务门槛；当前不据此阻塞合成功能实施。

## 9. 工程归属与完成边界

复用 run.py、模型发现和适用的基础设施，新增独立的数据与实验契约，不把分组输入或 latent 伪装成旧四张量接口。新数据流先标“在建”，不替代现有 TFs_type 主线；具体源码判断、文件与工作包统一见实施规格。

完整可重载模型、合成训练／测试／forecast、机制与多站点验收及可追溯产物全部真实执行，才称“功能实现完成”。业务是否值得采用另以真实数据验证。文档通过、forward 成功、阶段 A 完成或周期 smoke 都不能代替整体交付。

实现若无收益可停用独立路由并保留实验记录，不破坏原主线。模型开发、删除文件、依赖变更和提交／发布仍遵守根治理与用户授权边界。
